# FASE 3 · BACKEND · Los cambios del esquema SQL, paso a paso

> **Creada en:** Fase 1 · **Se llena en:** Fase 3 · **Estado actual:** vacía

Cada cambio de la base de datos es un fichero `.sql` **nuevo**, numerado por
fecha. Nunca se edita uno anterior.

Aplicar todos en orden desde cero debe reproducir exactamente la base de datos
actual. Eso es lo que permite montar un entorno de pruebas idéntico al real, o
recuperarse de un desastre.
